# Testing

Every host test and check of the library runs through one command at the root of the repository, `test.cmd`. The command works from
cmd, PowerShell, bash and zsh. It needs CMake and a GCC, and nothing else is required.

## Running

```text
./test.cmd                  every test whose tools are present
./test.cmd VUB              the tests of one module, by its label
./test.cmd VUB Memory       the tests of several modules
./test.cmd -L size          the tests of one kind: host, fail, size, check or tool
./test.cmd -R Header        the tests whose names match a regular expression
./test.cmd -R Cobs -R Crc   -R may be given more than once: the expressions are joined with '|'
./test.cmd -j 8 -V          anything that starts with '-' goes to CTest as it is
./test.cmd --list           the tests and their labels, nothing is run
./test.cmd --sanitize VUB   the host tests of one module, built with the sanitizers (see Sanitizers)
```

In PowerShell, write `.\test.cmd`. From cmd, write `test.cmd` in a folder where the command is on the search path, or `.\test.cmd`.
The exit code is 0 when every selected test passes or is skipped, and 1 when the configure fails, a selected test fails, or, in a run
without a module name, the build fails. With module names, a module that is not selected does not affect the result: a selected test
whose executable is missing fails by itself.

## Requirements

| Tool | Used for | Version |
|------|----------|---------|
| CMake | configuring, building and running the tests | 3.25 or newer |
| g++ | every host test and snippet | GCC 14 or newer; `CXX` picks the compiler, `g++` when it is not set |
| Ninja | faster builds | optional; the platform's generator is used without it |
| arm-none-eabi-g++ | size measurements | GCC 14 or newer; `ARM_CXX` picks the compiler, `ARM_SIZE` the size tool |
| Node and npm | the tests of the bootloader CLI | optional |
| .NET SDK | the tests of the C# counterpart tools | optional |

A test whose tool is missing is skipped, and the log says so. A skipped test does not fail the run.

A host test that cannot run in its environment prints the line `VHAL_SKIP:` followed by the reason, and exits. The test is then
reported as skipped with that reason, and it does not fail the run. The marker is the same one that the size, check and tool
tests use.

## Build folder

The build folder is `.test-build/` at the root, and it is ignored by git. It is kept between runs, so a run rebuilds only what
changed since the last one. Each run configures the folder again with the compiler that `CXX` names at that time. The sanitizer
run has its own folder, `.test-build-sanitize/`, which is also ignored.

## Sanitizers

`./test.cmd --sanitize` builds every host test (the `vhal_test` targets) with the address and undefined-behaviour sanitizers:
`-fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer` on the compile and the link. The fail, size, check
and tool tests are not built with them.

Each host test runs with `ASAN_OPTIONS=exitcode=1:detect_leaks=1` and `UBSAN_OPTIONS=exitcode=1:halt_on_error=1:print_stacktrace=1`
set by the frame. A sanitizer report stops the program and exits with 1, so it fails its test.

The configure first builds and runs a program with the same flags. When the compiler cannot do that, the configure stops with a
message that names the compiler and the cause, and no test runs. An explicit request for sanitizers does not skip them silently.
The MinGW toolchain on Windows has no sanitizer runtime, so `--sanitize` stops there. The Linux runner of the continuous integration
runs `./test.cmd --sanitize -j 4` with GCC 14.

## Header checks

`vhal_headers(<header>... [INCLUDES dirs] [OPTIONS flags])` declares one test per header, named `<label>.check.Header_<file stem>`.
When two headers of one call share a file stem, their names carry the folder as well: `Header_<folder>_<file stem>`. Each header is
the only include of a translation unit, and that unit must compile with `-fsyntax-only -std=c++23 -Wall -Wextra -Werror`, and with
the `OPTIONS` flags. The header is included by the path it has under the first include root that holds it, so the test checks the
spelling that a consumer uses.

The modules that check their headers this way are COBS, RegisterBus, Modbus, VUB and RegisterMap.

## The nm tool

`VHAL_ARM_NM` names the nm tool of the ARM objects. It is derived from `VHAL_ARM_CXX` (`arm-none-eabi-g++` gives
`arm-none-eabi-nm`) unless the `ARM_NM` environment variable or the `-DVHAL_ARM_NM` option gives another one. Every scripted check
receives it as the `VHAL_ARM_NM` script variable. A check that reads the host objects uses the host nm, found next to the host
compiler, because an ARM nm cannot read them.

## Labels and names

Every test carries two labels: the name of its module folder, and its kind.

| Kind | What it is |
|------|------------|
| `host` | a host test executable, built with `-std=c++23 -Wall -Wextra -Werror` and run |
| `fail` | a compile-fail snippet: it must not compile, and its diagnostic must contain the text of its first line |
| `size` | a size measurement with the ARM compiler, which fails when a cost is above its limit |
| `check` | a scripted check that is neither of the above, such as a run-time failure or a fixture check |
| `tool` | the tests of a counterpart program in the `.tool` folder |

The name of a host test is `<label>.<name>`, for example `VUB.TestVubReliableWire`. The name of any other test is
`<label>.<kind>.<name>`, for example `VUB.fail.memory_step_twice`.

## Layout

Each module keeps everything that checks it in `<module>/.test/`: the tests, the snippets that must not compile, the shims, the size
measurements and their fixtures. Its `<module>/.tool/` folder holds only the PC programs that talk to a device, and the code they
share with the device.

The root project is `.test/CMakeLists.txt`. It adds the `.test` folder of every module under `Common` and `Periphery`, and it skips
the vendor folders of the ports and the FreeRTOS kernel. The functions the modules call are in `.test/VhalTest.cmake`.

## Adding a test to a module

A module declares its tests in `<module>/.test/CMakeLists.txt`:

```cmake
vhal_test(GLOB Test*.cpp INCLUDES "${VHAL_ROOT}/Common")

vhal_fail(BuilderErrors INCLUDES "${VHAL_ROOT}/Common")

vhal_size(size/Size.cmake)
```

| Function | Declares |
|----------|----------|
| `vhal_test(<source.cpp> ...)` | one host test executable; `INCLUDES`, `DEFINES`, `LIBS`, `OPTIONS`, `ARGS` and `SOURCES` set its build and run |
| `vhal_test(GLOB <pattern> ...)` | one host test for each file of the module folder that matches the pattern, with the same options |
| `vhal_fail(<dir> ...)` | one compile-fail test for each `*.cpp` file of the folder; `INCLUDES` and `OPTIONS` (extra compiler flags) |
| `vhal_headers(<header>... ...)` | one header-alone test for each header, named `<label>.check.Header_<stem>` |
| `vhal_size(<script.cmake>)` | one size measurement, run with `ARM_CXX` |
| `vhal_check(<script.cmake> [ARGS ...])` | one scripted check, run with `cmake -P` |
| `vhal_tool_test(<dir> [NAME <name>] [SCRIPT <npm script>] [PREPARE <npm script>])` | the tests of a counterpart tool, with `npm run test` (or `SCRIPT`) or `dotnet test`; `NAME` adds a last part to the test name, such as `Bootloader.tool.e2e`; `PREPARE` runs an npm script first when a g++ is on the PATH, and the test is skipped when that script fails |
| `vhal_declared(<pattern> <file>...)` | a guard: the configure fails when a file of the folder matches the pattern and is not one of the listed files |

The include directories are searched in the order given. A snippet of `vhal_fail` starts with a line `// expect: <text>`. Its
optional second line is `// one error`, which asks for exactly one error line in the diagnostic, or `// expect-value: <text>`, which
asks for the value `<text>` in the diagnostic: GCC prints it as `Value = <text>]` and Clang as `, <text>>`.

The diagnostic is read with the escapes of GCC undone: `\\` is a backslash and `\'` is a quote, as a template argument prints them.
The compiler runs with `LC_ALL=C`, so its messages are in English whatever the locale of the machine is.

## Writing a host test

A host test is a source file that `vhal_test` declares. It includes `VhalCheck.h`, runs its checks in `main` and ends with
`return VhalCheck::Finish("<test name>")`. The check header is `.test/include/VhalCheck.h`, and the frame adds its folder to the
include path of every host test.

```cpp
#include <VHAL.h>
#include <VhalCheck.h>


int main() {
	VHAL_CHECK(buffer.Empty());
	VHAL_CHECK_EQ(buffer.Size(), 3u);
	VHAL_CHECK_EQ(state, State::ready);
	VHAL_CHECK_NEAR(filter.Output(), 0.5, 1e-6);

	return VhalCheck::Finish("TestBuffer");
}
```

| Macro or function | Holds when |
|-------------------|------------|
| `VHAL_CHECK(condition)` | the condition is true; a failure prints the file, the line and the expression |
| `VHAL_CHECK_EQ(actual, expected)` | the two values are equal. Integers of any signedness compare by value, enums by their underlying value, `bool` by its value, and text (a string literal, a `const char*` or a `std::string_view`) by its characters |
| `VHAL_CHECK_NEAR(actual, expected, tolerance)` | the absolute difference of the two values, as `double`, is at most the tolerance |
| `VhalCheck::Finish(name)` | prints the summary and returns the exit code of the program |

A floating-point value in `VHAL_CHECK_EQ` is a compile error that names `VHAL_CHECK_NEAR`, and a pointer that is not text is a compile
error that names `VHAL_CHECK`. Every check counts toward the total that `Finish` prints.

A failed check prints `<file>:<line>: check failed: ...` with the values to stderr. The summary goes to stdout: `<name>: <n> checks
passed` when every check held, and `<name>: <f> of <n> checks failed` otherwise. The program exits with 0 or 1.

### The shared shim

`.test/shim/VHAL.h` is the host stand-in for the umbrella header `VHAL.h`. It includes the real `System/System.h` and defines the
System functions that a portable module reaches:

- critical sections: a section is a depth and a count of enters. `VhalSim::CriticalDepth()` and `VhalSim::CriticalEnters()` read
  them, and a leave with no open section aborts;
- `Abort` and `CriticalError` print the message, the file and the line to stderr, and call `std::abort()`;
- a simulated clock: `GetTick`, `GetTick32`, `GetMs`, `DelayMs` and `DelayUs` read and advance one counter. `VhalSim::AdvanceMs(uint32)`
  and `VhalSim::SetMs(uint64)` move it. A delay moves the clock by whole milliseconds, rounded up;
- `IsInterrupt()` returns false.

The shim lives in the frame, so a module needs no copy of it. The include roots of a host test are searched in this order: the
roots the module gives in `INCLUDES`, then `.test/include`, then `.test/shim`. A header that an earlier root supplies hides the shim:
the `Periphery` folder has the umbrella header itself, so a module whose roots include it gets the library's `VHAL.h` unless its own
shim folder comes first.

### Overriding the shim

A module that needs its own stand-in for `VHAL.h` keeps it in `<module>/.test/shim/VHAL.h` and lists that folder first in `INCLUDES`.
The tests of the trigger module do this:

```cmake
vhal_test(
  GLOB Test*.cpp
  INCLUDES
    shim
    "${VHAL_ROOT}/Periphery"
    "${VHAL_ROOT}/Common")
```

A module whose include roots do not reach a `VHAL.h` uses the shared shim, and needs no `shim` folder in `INCLUDES`.

## Continuous integration

The workflow `.github/workflows/test.yml` runs on pushes to `Dev` and `main`, on pull requests, and when started by hand. It has three
jobs:

- `linux` runs on Ubuntu 24.04 with GCC 14 and Ninja, from bash: `./test.cmd -j 4`.
- `sanitizers` runs the same host tests with the sanitizers, on the same system: `./test.cmd --sanitize -j 4`.
- `windows` runs on the Windows runner with the UCRT64 compiler, CMake and Ninja of MSYS2, from cmd: `.\test.cmd -j 4`.

The size tests and the tool tests are skipped on the runners unless their tools are installed, and the log of each job says which
tests were skipped.
