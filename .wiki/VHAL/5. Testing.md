# Testing

Every host test and check of the library runs through one command at the root of the repository, `test.cmd`. The command works from
cmd, PowerShell, bash and zsh. It needs CMake and a GCC, and nothing else is required.

## Running

```text
./test.cmd                  every test whose tools are present
./test.cmd VUB              the tests of one module, by its label
./test.cmd VUB Memory       the tests of several modules
./test.cmd -L size          the tests of one kind: host, fail, size, check or tool
./test.cmd -j 8 -V          anything that starts with '-' goes to CTest as it is
./test.cmd --list           the tests and their labels, nothing is run
```

In PowerShell, write `.\test.cmd`. From cmd, write `test.cmd` in a folder where the command is on the search path, or `.\test.cmd`.
The exit code is 0 when every selected test passes or is skipped, and 1 when the configure, the build or a test fails.

## Requirements

| Tool | Used for | Version |
|------|----------|---------|
| CMake | configuring, building and running the tests | 3.25 or newer |
| g++ | every host test and snippet | GCC 14 or newer; `CXX` picks the compiler, `g++` when it is not set |
| Ninja | faster builds | optional; the platform's generator is used without it |
| arm-none-eabi-g++ | size measurements | GCC 14 or newer; `ARM_CXX` picks the compiler, `ARM_SIZE` the size tool |
| Node and npm | the tests of the bootloader CLI | optional |
| .NET SDK | the tests of the C# counterpart tools | optional |

A test whose tool is missing is skipped, and the log says so. A skipped test does not fail the run.

## Build folder

The build folder is `.test-build/` at the root, and it is ignored by git. It is kept between runs, so a run rebuilds only what
changed since the last one. Each run configures the folder again with the compiler that `CXX` names at that time.

## Labels and names

Every test carries two labels: the name of its module folder, and its kind.

| Kind | What it is |
|------|------------|
| `host` | a host test executable, built with `-std=c++23 -Wall -Wextra -Werror` and run |
| `fail` | a compile-fail snippet: it must not compile, and its diagnostic must contain the text of its first line |
| `size` | a size measurement with the ARM compiler, which fails when a cost is above its limit |
| `check` | a scripted check that is neither of the above, such as a run-time failure or a fixture check |
| `tool` | the tests of a counterpart program in the `.tool` folder |

The name of a host test is `<label>.<name>`, for example `VUB.TestVubReliableWire`. The name of any other test is
`<label>.<kind>.<name>`, for example `VUB.fail.memory_step_twice`.

## Layout

Each module keeps everything that checks it in `<module>/.test/`: the tests, the snippets that must not compile, the shims, the size
measurements and their fixtures. Its `<module>/.tool/` folder holds only the PC programs that talk to a device, and the code they
share with the device.

The root project is `.test/CMakeLists.txt`. It adds the `.test` folder of every module under `Common` and `Periphery`, and it skips
the vendor folders of the ports and the FreeRTOS kernel. The functions the modules call are in `.test/VhalTest.cmake`.

## Adding a test to a module

A module declares its tests in `<module>/.test/CMakeLists.txt`:

```cmake
vhal_test(GLOB Test*.cpp INCLUDES "${VHAL_ROOT}/Common")

vhal_fail(BuilderErrors INCLUDES "${VHAL_ROOT}/Common")

vhal_size(size/Size.cmake)
```

| Function | Declares |
|----------|----------|
| `vhal_test(<source.cpp> ...)` | one host test executable; `INCLUDES`, `DEFINES`, `LIBS`, `OPTIONS`, `ARGS` and `SOURCES` set its build and run |
| `vhal_test(GLOB <pattern> ...)` | one host test for each file of the module folder that matches the pattern, with the same options |
| `vhal_fail(<dir> ...)` | one compile-fail test for each `*.cpp` file of the folder |
| `vhal_size(<script.cmake>)` | one size measurement, run with `ARM_CXX` |
| `vhal_check(<script.cmake> [ARGS ...])` | one scripted check, run with `cmake -P` |
| `vhal_tool_test(<dir>)` | the tests of a counterpart tool, with `npm test` or `dotnet test` |

The include directories are searched in the order given. A snippet of `vhal_fail` starts with a line `// expect: <text>`, and a
second line `// one error` asks for exactly one error line in its diagnostic.

## Continuous integration

The workflow `.github/workflows/test.yml` runs on pushes to `Dev` and `main`, on pull requests, and when started by hand. It has two
jobs:

- `linux` runs on Ubuntu 24.04 with GCC 14 and Ninja, from bash: `./test.cmd -j 4`.
- `windows` runs on the Windows runner with the UCRT64 compiler, CMake and Ninja of MSYS2, from cmd: `.\test.cmd -j 4`.

The size tests and the tool tests are skipped on the runners unless their tools are installed, and the log of each job says which
tests were skipped.
